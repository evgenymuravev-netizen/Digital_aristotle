# Опрос по контурам — стратегия и культура

Диагностика **общего контекста команды**. В отличие от остальных приложений
проекта (MMAT, System Analyst Assessment) это **не тест со счётом**: здесь нет
правильных ответов, баллов, процентилей, сертификата и античита. Мы меряем
**сходимость** ответов — насколько одинаково команда понимает стратегию (контур 1)
и культуру (контур 2), — а не уровень отдельного человека.

Живая ссылка: `/contours/` · отчёт фасилитатора: `/contours/report.html`

Инструмент основан на «Фреймворке устойчивого окружения» (Л. Гончаров): порядок
чтения строгий — сначала контур 1 (стратегия как рамка), потом контур 2 (культура).
Дефект К1 объясняет К2, но не наоборот.

## Что переиспользовано из прошлых приложений

Пригодилось (и переиспользовано):
- **Дизайн-система** Alethia (тёмный лес + лайм) — те же токены и `styles.css`.
- **Оболочка раннера**: один вопрос на экране, прогресс, двуязычность (RU/EN,
  переключатель в шапке; RU по умолчанию через `localStorage["contours:lang"]`).
- **Публикация отдельной ссылкой** через общий GitHub Pages деплой (`/contours/`).
- **Полностью статично**: обычные `<script>` (не модули), работает и по `file://`.

Сознательно **не** переносилось — сломало бы инструмент:
- счёт / процентиль / рейтинг / сертификат — здесь нет «правильно»;
- античит и прокторинг — мы не ловим человека, а читаем дисперсию группы;
- персонализация и подбор под вакансию — вопросы фиксированы, порядок фиксирован.

## Особенности прохождения (важно для валидности)

- **Жёсткий кап на каждый вопрос** с автопереходом (это не общий таймер, а способ
  поймать первую реакцию: у A1 — 15 c, у открытых — до 90 c, у мета — 5 c).
- **Назад нельзя.** Изменить ответ, увидев следующий вопрос, — уже не тот сигнал.
- **Пропуск — это данные** (метрика «молчание»), а не «нет ответа».
- **Латентность** (время до первого действия) пишется в ответ.
- **Порядок фиксирован** A → B; лид отвечает первым и служит точкой отсчёта
  каноничности.
- **Анонимность**: агрегат в срезе показывается только при `minN` (5+) ответах.

## Как запустить волну

1. **Настройте `config.js`** — все значения, помеченные `DEMO`, заменяются на своё:
   - `org.strategyGoal`, `org.keyMetric`, `org.values` (3 реальные ценности) —
     подставляются прямо в формулировки (A5, A6, B2, B3);
   - списки `a2_directions` (12: реально отвергнутые / в работе / дистракторы),
     `a3_metrics`, `a6_scale`, `a7_threats`, `a10_resource`, `a11_behaviors`,
     `b1_values` (15: реальные / близкие / универсальные), `b8_reaction`,
     `b11_behaviors`. Поле `kind`/`ext` — «истина» для чтения каноничности,
     респондент его не видит.
2. **Раздайте ссылку** `/contours/` команде. Все вводят **один и тот же ключ группы**
   (`groupKey`) — он склеивает ответы. Лид отмечает галочку «Я — лид».
3. **Сбор ответов** — два пути:
   - по умолчанию респондент **скачивает файл** ответа и передаёт фасилитатору;
   - либо задайте `submitEndpoint` (Formspree / Cloudflare Worker / Supabase) —
     ответы уйдут POST-запросом автоматически. Ключей/секретов в `config.js` нет
     и быть не должно (файл уезжает в браузер).
4. **Дайте волне 5–7 дней** и минимум 5 ответов в срезе, потом стройте отчёт.

## Отчёт фасилитатора (`report.html`)

Открывает фасилитатор. Вставляет собранные файлы (JSON-массив или по одному в
строке) или загружает их кнопкой; кнопка **«Демо-данные»** синтезирует ~7 ответов,
чтобы посмотреть, как выглядит отчёт. Всё считается **в браузере**, ничего не
отправляется.

Что показывает (пороги стартовые, не откалиброваны — читайте **сравнение блоков и
динамику**, а не абсолют; **единого индекса нет и не должно быть**):

- **IoA** (индекс согласия) по каждому закрытому вопросу: `1 − H/H_max`
  (энтропия), для multi — средний Jaccard.
- **Каноничность** — доля команды, совпавшая с лидом.
- **Δ-разрыв** (A11/B11) — «реально поощряют» ≠ «должны поощрять».
- **Мета-разрыв** по блоку — фактический IoA vs ожидаемый (из мета-вопроса):
  плюс — плюралистическое неведение (дешёвый ремонт: показать команде агрегат),
  минус — иллюзия согласия (опаснее: не перепроверяют).
- **Молчание** — доля пропусков по блоку.
- **Семантическая дисперсия** (B2) — приближение по токенам (настоящая
  кластеризация требует ручного/модельного кодирования).
- **Сегментация** — раскладка дисперсии по стажу/функции/локации (структурная
  фрагментация лечится иначе, чем общая размытость).
- **Открытые ответы** — выводятся списком для ручного кодирования; чувствительные
  (B4/B10) скрыты при малом N.

## Файлы

| Файл | Назначение |
|------|-----------|
| `index.html` | оболочка раннера (noindex) |
| `config.js` | `window.CONTOURS_CONFIG` — контент компании/волны (замените `DEMO`) |
| `survey.js` | `window.SURVEY` — определение инструмента (24 вопроса / 28 экранов, 2 блока; A9 → a/b/c, A11/B11 → «реально»/«должно») |
| `app.js` | раннер: кап, автопереход, латентность, выгрузка ответа |
| `metrics.js` | `window.CONTOURS_METRICS.compute()` — IoA/каноничность/Δ/мета/молчание/семантика |
| `report.html` | отчёт фасилитатора (импорт файлов, демо-данные, диагностика) |
| `styles.css` | тема Alethia + компоненты раннера/отчёта |

## Проверки

```sh
node --check config.js && node --check survey.js && node --check app.js && node --check metrics.js
node test-metrics.mjs   # юнит-тест метрик на синтетических данных (37 проверок)
node test-runner.mjs    # смоук-тест раннера под DOM-шимом: проход всех экранов (11 проверок)
```

Индексация закрыта (`robots.txt` + `<meta name="robots" content="noindex">`):
инструмент рассчитан на приватные волны по ссылке, а не на публичный трафик.
