# Дизайн v0.2 — К1–К2 через личные эпизоды К3–К4

**Статус: дизайн, не реализовано.** Основано на «Фреймворке устойчивого
окружения» (4 контура, проверки на диссонансы/синергии) и методике запуска.
Цель ревизии: **целевые контуры — 1 и 2**, но **все вопросы задаются через
личный опыт респондента в контурах 3–4** (договорённости, поведение
окружающих, собственные действия/бездействия, личный ресурс).

## 1. Принцип

Фреймворк сам это диктует:

- К3 — «живая регуляция», и **расхождение слов и дел здесь — самый громкий
  сигнал**, что сломан один из контуров выше.
- «Любые конфликты, тайные правила, персональный героизм — прямой и самый
  приоритетный сигнал изучения и изменения в одном из контуров».
- Прямые вопросы про К1/К2 («понятна ли вам стратегия?») меряют лояльность и
  социальную желательность. Эпизод («что произошло, когда ты в последний раз
  …») меряет реальность: человек вспоминает конкретное событие из своего
  контура 4 и отмечает наблюдаемый исход.

Механика: **каждый закрытый вариант ответа несёт разметку** — на какую
составляющую К1/К2 он грузится, с каким знаком (синергия/диссонанс) и какой
конфликт пары контуров сигналит. Дальше всё считается из закрытых ответов —
без ИИ и без ручного кодирования.

Побочный выигрыш анонимности: эпизод **не описывается текстом** — хранится
только категория исхода. Часть открытых вопросов можно убрать совсем.

## 2. Составляющие и датчики

| Контур | Составляющие | Роль в опросе |
|---|---|---|
| К1 — основы и направления | **S** Стратегия · **V** Ценности | цель измерения |
| К2 — закрепление практик | **St** Структуры · **C** Культура | цель измерения |
| К3 — взаимодействие | **D** Договорённости · **P** Поведение (реакция системы) | датчик |
| К4 — действие/бездействие | **R** Личный ресурс, действия | датчик |

Датчики не «оцениваются» как цель — они (а) источник эпизодов, (б) проверка
достоверности показаний: если в К3/К4 страх и молчание, показания о К1/К2
занижены (конформны), и отчёт обязан это маркировать.

### Стартовый экран — одно добавление

«Сколько времени эта команда уже работает вместе и сколько ещё планирует?»
(a) временная — месяцы · (b) год-два · (c) долгоживущая. Из третьего
документа: **у временной группы важнее связь с лидом (канон), у долгоживущей —
IoA.** Отчёт подписывает, какой из двух показателей ведущий для этой группы.

## 4. Математика

### 4.1 Разметка (матрица нагрузок)

Каждый закрытый вариант `o` вопроса `i` несёт:

```
w(i,o) ∈ {−2,−1,0,+1,+2} на каждую из {S, V, St, C}   — нагрузка со знаком
sens(i,o) ∈ {D+, D−, P+, P−, R+, R−, ∅}                — показание датчика
conf(i,o) ∈ {К1↔К2, К1↔К3, К1↔К4, К2↔К3, К2↔К4, К3↔К4, ∅} — метка конфликта
```

В коде это поле `code:` рядом с каждым вариантом в `survey.js` — ни ИИ, ни
ручного кодирования для основного отчёта не нужно.

### 4.2 Два независимых показателя каждой составляющей

Для компоненты c ∈ {S, V, St, C}:

- **Сходимость** `IoA_c` — средневзвешенное IoA по вопросам, грузящимся на c
  (веса |w|). «Одинаково ли группа видит c». Существующая математика
  (энтропия / Jaccard), сгруппированная по компонентам вместо блоков.
- **Валентность** `Val_c = Σ w(i,o)·n(o) / Σ |w(i,o)|·n(o) ∈ [−1,+1]` по
  эпизодным вопросам. «Здорова ли c в реальных событиях».

**Читать строго парой** — это четыре разных диагноза:

| | Val высокая | Val низкая |
|---|---|---|
| **IoA высокая** | синергия — контур работает | **консенсус о поломке** — все видят одно и то же плохое; лучший случай для ремонта |
| **IoA низкая** | размытость — общей картины нет | фрагментация + боль — худший случай |

Сводить в одно число нельзя: IoA=высокий/Val=низкий и IoA=низкий/Val=высокий
дадут одинаковую «среднюю», а лечатся противоположно.

### 4.3 Матрица конфликтов контуров

`Conf(a↔b)` = доля ответов с меткой a↔b среди всех данных эпизодных ответов.
Выводится верхний треугольник 4×4 с именами из фреймворка:

| Конфликт | Имя | Питается от | Что означает |
|---|---|---|---|
| К1↔К2 | «Ценности против правил» | B3(b,d), A13(d), **Δ A11/B11** | декларируется одно, выгодно другое — ядро фреймворка |
| К1↔К3 | «Цель через конфликт» | A13(e) | движение к цели = «белая ворона», жертвенность |
| К1↔К4 | «Цель против человека» | A13(f), B3(e), A4(d) | по фреймворку — худшее: «заставим людей идти против себя» |
| К2↔К3 | «Правила против жизни» | B7b, B8(a,e), B13(c), B14(c), B4a(b) | обходные тропы, тайные правила, договорённости без последствий |
| К2↔К4 | «Уклад на героизме» | B15(b,c), B3(c) | подвиг как режим работы |
| К3↔К4 | «Молчание» | B16(b,d), B14(e), молчание блока B | страх, «мне же хуже», не прошу помощи |

Δ из A11/B11 не отдельная метрика, а **вклад в Conf(К1↔К2)**: доля тех, у
кого «реально поощряют» ≠ «должны поощрять».

Стартовые пороги (не откалиброваны, читать сравнение и динамику):
Conf < 0.10 — фон · 0.10–0.25 — внимание · > 0.25 — конфликт назван.

### 4.4 Достоверность датчика (гейтинг)

Индекс страха `F` = нормированная сумма долей: B16(d) «мне же хуже» ×2 ·
B16(b) «потерпеть» · B14(e) «не прошу — себе дороже» · B8 «ничего не
произойдёт» · молчание блока B.

- `F < 0.15` — датчик чистый;
- `0.15–0.35` — «показания занижены: в этой группе о проблемах говорить
  небезопасно, реальность хуже измеренной»;
- `> 0.35` — **отравленный датчик**: Val и Conf публикуются только с этим
  флагом, «зелёные» значения К1/К2 не считаются зелёными.

Никакой числовой «поправки» не выдумываем — честная маркировка вместо
псевдоточности. Существующая проверка конформизма (высокий IoA + высокое
молчание) — частный случай этого правила.

### 4.5 Порядок чтения отчёта (иерархия фреймворка)

1. Достоверность датчика (F) — можно ли верить остальному;
2. К1: (IoA_S, Val_S), (IoA_V, Val_V) — дефект здесь объясняет всё ниже;
3. К2: (IoA_St, Val_St), (IoA_C, Val_C);
4. Матрица конфликтов — что с чем воюет;
5. Мета-разрывы по блокам, сегментация, открытые ответы (доп. материал).

Ведущий показатель по типу группы: временная → канон, долгоживущая → IoA
(п. «Стартовый экран»). Прежнее правило «сначала контур 1, потом 2» сохранено
и усилено: конфликтная матрица прямо показывает, *какой* контур ломает *какой*.

## 5. Что это меняет в анонимности

Строго лучше v0.1: мастер-проверки и новые эпизодные вопросы **закрытые** —
сам случай не описывается, хранится категория исхода. Открытых остаётся три
(A1, B4, B10 + B7-строка), все — доп. материал, на математику не влияют.
Короткая версия обходится вообще без открытых. Вопрос об ИИ-кодировке
открытых становится менее острым (но остаётся опцией для глубины).

## 6. План реализации (когда будет отмашка)

1. `survey.js` v0.2: новые/ретул-вопросы + поле `code` на вариантах;
2. `config.js`: списки вариантов мастер-проверок (формулировки под компанию);
3. `metrics.js`: `components` (IoA_c, Val_c), `conflicts` (матрица), `fear`
   (гейтинг) — поверх существующих IoA/канон/Δ/мета/молчание;
4. `report.html`: блок «Составляющие К1–К2» (квадранты IoA×Val), «Конфликты
   контуров» (треугольная матрица), бейдж достоверности датчика;
5. тесты: нагрузочная таблица (каждый вариант размечен), Val/Conf/F на
   синтетике; проверка «квадрантов».
